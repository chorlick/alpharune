# Riftbound Simulation Engine — Standards & Guidelines

C++20 game engine that simulates 1v1 Riftbound TCG matches. This file is the standards and conventions reference for engine development. For project status, completed work, and active backlog, see git log + the sibling riftbound-trainer repo's `docs/`.

## Build

```bash
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j6
RIFTBOUND_ROOT=. ./build/riftbound_tests
RIFTBOUND_ROOT=. ./build/src/openspiel/riftbound_openspiel_tests
```

`riftbound_tests` links only `riftbound_core`. The OpenSpiel wrapper (`RiftboundGame` / `RiftboundState`, clone and history replay, `MctsAgent` / `IsMctsAgent`) is tested by the separate `riftbound_openspiel_tests` binary (`src/openspiel/openspiel_tests.cpp`), which is not part of `riftbound_tests`: build and run both.

First configure clones OpenSpiel v1.6.14 + abseil-cpp + nlohmann/json + pybind11_json + DDS into `build/_deps/` (~10s configure + one-time ~30s build of `open_spiel_core`). OpenSpiel is mandatory — the MCTS/ISMCTS agents in the `riftbound` binary (`src/agents/mcts_agent.cpp`) depend on it.

**Build structure.** `src/pch.h` is precompiled once (`riftbound_pch`) and reused by `riftbound_core` and the card groups. Each `src/cards/<type>/` directory is an OBJECT library (`riftbound_cards_<type>`) folded into `riftbound_core`, compiled as unity batches. Options: `-DRIFTBOUND_USE_PCH=OFF`, `-DRIFTBOUND_UNITY_CARDS=OFF` (one compile per card, e.g. for clangd), `-DRIFTBOUND_CARD_UNITY_BATCH=<n>` (default 16). `-DRIFTBOUND_WARNINGS=OFF` drops `-Wall -Wextra` (on by default for engine targets, never `-Werror`). **Optimisation:** `-DRIFTBOUND_TEST_OPT_LEVEL=0` compiles only the `riftbound_tests` sources at `-O0` and leaves the engine and cards at the build type's level — the development setting: at `-O3` the test sources are 52% of a full rebuild (398 of 773 CPU-s, 2026-10-11) and the suite's run time is spent in the engine, not in test code. `-DRIFTBOUND_OPT_LEVEL=<0|1|2|3|g|s>` sets the level for every target, third-party included; at `0` our own code compiles in 400 CPU-s instead of 701 but the suite runs in 61 s instead of 19 s, so it pays only for edit-and-run-one-test loops. Both default to empty (the build type decides); anything that is timed or shipped uses the default.

**Parallelism cap.** `-DRIFTBOUND_BUILD_JOBS=<n>` (default 6, `0` = no cap) is a Ninja job pool shared by every compile and link, third-party targets included: `cmake --build build -j16` still runs at most `n` at once. Ninja generators only.

**ccache.** Configure with `-DCMAKE_CXX_COMPILER_LAUNCHER="env;CCACHE_SLOPPINESS=pch_defines,time_macros;$PWD/scripts/ccache_pch_safe.sh"` (run from the checkout root). `pch_defines,time_macros` is what lets compiles that use the PCH be cached at all. **The launcher must be `scripts/ccache_pch_safe.sh`, not `ccache`.** For a compile that creates a PCH the script deletes the old `.gch`, runs the compiler directly (**a PCH is always compiled, never stored in or taken from the cache**) and writes `<pch>.gch.sum`: a SHA-256 of the compiler version, the PCH compile's command line and the name and raw bytes of every file the compiler read (from the depfile). Every other compile goes to ccache with `pch_external_checksum` on, so a unit that uses the PCH is keyed on that `.sum` instead of on the `.gch` bytes (GCC does not write identical `.gch` files for identical inputs). Plain ccache gets a cached PCH wrong in two ways, both reproduced on copies of this repository (2026-10-11): (1) CMake rebuilds a PCH with the old `.gch` still in place; ccache takes the compile for one that *uses* that `.gch` and keys the result on it instead of on the headers, so two rebuilds that start from the same `.gch` share one result (a worktree got a `.gch` built from another worktree's headers). (2) From a clean build directory, with the cache holding the PCH for the previous headers, a comment **reworded in place** (same line count) leaves the preprocessed text unchanged, so ccache restores the previous `.gch`; its `#pragma once` record for that header no longer matches the file, and the first unit that is really compiled includes the header twice (`redefinition of kInvalidId`). A comment edit that adds or removes a line changes the preprocessed text and does not trigger it; units that are themselves cache hits hide it. A clean build does not avoid (2): it is what exposes it. CMake warns at configure time if PCH is on and the launcher is plain ccache. Cost, measured on a no-change clean rebuild of `riftbound_tests` at `-j3`: 14 s with 109 of 109 compiles from the cache; without the `.sum` (PCH never cached, units keyed on the `.gch` bytes) it was 222 s with 2 of 108. The `.sum` covers file paths, so checkouts at different paths do not share PCH-using objects; to keep a tree's cache to itself add `CCACHE_NAMESPACE=<name>`. `scripts/check_ccache_pch_launcher.sh` re-runs both reproductions and the hit/miss checks on scratch copies with a cache of their own (a few minutes, exit 0 = pass): run it after upgrading ccache or the compiler and after any change to the launcher.

**Tests are unity-built too.** `riftbound_tests` compiles `tests/**/*.cpp` in batches (`-DRIFTBOUND_UNITY_TESTS=OFF` for one compile per test file, e.g. while iterating on a single file or for clangd; `-DRIFTBOUND_TEST_UNITY_BATCH=<n>`, default 8). File-scope names in a test file must therefore be unique across `tests/`: put a file's helpers, test cards and fixtures in a namespace of its own (`namespace riftbound::test::<file>`), not in a bare anonymous namespace. A clash is a compile error in the batch that pairs the two files; a file that cannot share a unit is listed in `RIFTBOUND_TEST_UNITY_EXCLUDE` in `CMakeLists.txt`.

**Card files share a translation unit with their neighbours.** File-scope names in a card file must be unique within its directory: a reprint's class carries its card id (`KarmaChanneler_235` / `KarmaChanneler_548`), and helpers needed by more than one card go in `src/cards/card_helpers.h` rather than being copied.

**Dependencies:** cmake, g++ (C++20), libboost-all-dev, nlohmann-json3-dev, ninja-build.

Training pipelines (model architectures, self-play loops, checkpoints) live in the sibling **riftbound-trainer** repo. Engine repo has no torch dependency.

## Coding Standards

### C++ Style
- **C++20** standard, `-std=c++20`
- **Namespace:** `namespace riftbound` for all engine code
- **Headers:** `#pragma once`, no include guards
- **Naming:** `PascalCase` types/enums, `camelCase` methods/variables, `snake_case` file names, `kConstant` constants
- **Includes:** project headers use `"core/types.h"` relative to `src/`, system headers use `<>`
- **Strong types:** Enums and tagged IDs over raw ints. `PlayerId`, `GameObjectId`, `BattlefieldId`, etc. **Every id kind is a type of its own** (`StrongId<Tag>` in `core/types.h`: `CardDefId`, `GameObjectId`, `BattlefieldId`, `BattlefieldPoolIndex`, `ChainItemId`, `AbilityId`): two kinds do not mix and an integer is not an id. To and from a number only by name: `id.raw()` (a log line, an int slot such as `resume_data` or a `card_counters` value, an index) and `X::fromRaw(n)`; text is `toString(id)`, not `std::to_string`. `kInvalidId` is the one "none" of every kind and what a default-constructed id is (`id == kInvalidId`, `id.valid()`); in a plain integer slot none is `kInvalidId.raw()` (-1 in a signed slot). Only a card id converts from an integer **literal** (`d.id = 235`, `registry.get(235)`; consteval, so not from a variable and not from 0); a battlefield slot is named `BattlefieldLocation{0}` or `BattlefieldId::fromRaw(0)`. `state.battlefields[bf_id]` indexes by id. `tests/test_strong_ids.cpp` and the `riftbound_strong_id_case_*` ctests (`tests/compile_fail/strong_id_mix.cc`) keep the mixes from compiling.
- **No raw owning pointers:** Use references, `std::optional`, containers. Objects live in `GameState::objects` map.
- **Error handling:** `assert()` for invariant violations, `throw` for invalid input, return codes for expected failures (e.g. deck validation).

### Architecture Patterns
- **Event Bus** (Boost.Signals2): Actions emit events, subsystems subscribe. How triggered abilities, cleanup, logging, and rendering are wired. See `src/core/events.h`.
- **Intent/Command:** Every player action is an `Intent` struct. Engine enumerates legal intents, agent picks one, engine validates and executes. See `src/core/intent.h`.
- **Dependency Injection:** Subsystems (cleanup, combat, renderer, logger) are injected into the engine, not constructed by it. Makes testing easy — inject mocks.
- **Immutable CardDef, mutable GameObject:** `CardDef` (from registry) is static. `GameObject` is the runtime instance with current state. A `GameState` is copied for every search node, so what an object holds is kept cheap to copy: `name` / `tags` / `domains` are `Interned<T>` (`core/interned.h`, one pointer to a shared constant value; they read as the `std::string` / vector they stand for and are written by assignment, `push_back`, `clear` or `edit(fn)`; with a literal in a `?:` say `obj.name.get()`), and `card_counters` / `string_state` are `KeyedSlots<V>` (`core/keyed_slots.h`: the map spelling `[]` / `find` / `end` / `count` / `erase` / `at` / `empty`, a reference to an entry stays valid while the entry exists, there is no iteration in a defined order). `riftbound_clone_breakdown` prints what one copy costs per member; `sizeof(GameObject)` is bounded by a `static_assert` in `tests/test_object_copy_cost.cpp`.
- **Fiber-based step machine:** `boost::context::fiber` lets the engine yield at decision points without spawning OS threads. See `src/engine/step_driver.h`.

### Testing
- Google Test framework, tests in `tests/`, files named `test_<module>.cpp`.
- Tests cover behavioral boundaries, not 100% line coverage.
- Per-card tests under `tests/cards/` use the shared `tests/cards/card_test_fixture.h`. Card behaviour is tested through the real engine path (`playThroughEngine` / `fireTriggerThroughEngine` / `resolveThroughEngine` with an `EnginePathAgent`); the direct-call helpers never hand a trigger targets, because the engine never does.
- CardDB is built from the card classes (`buildFromClasses`); tests use `RIFTBOUND_ROOT` only to locate sibling data dirs like `decks/`.
- **Whole-pool fuzz** (`tools/deck_fuzz.cpp`, target `deck_fuzz`, not part of `all`): random agents play random constructed-legal decks. `RandomDeckBuilder` (`rules/random_deck.h`) turns a 64-bit seed into a deck `DeckValidator` accepts (legend, its champion, 39 cards of the legend's Domains, 12 runes, 3 battlefields; no banned card, no token card, a [Unique] card once); every card that is legal in some deck is in some seed's deck. A game is identified by (deck seed A, deck seed B, game seed) and by nothing else, so any game replays alone. The large run: `cmake --build build --target deck_fuzz -j3`, then `RIFTBOUND_ROOT=. ./build/deck_fuzz --decks 5000 --games-per-pair 20 --seed <S> --threads 3 --json out.json` (100,000 games, about 9 minutes on 3 threads; `--deck-dir decks --games-per-pair 200` plays every ordered pairing of the deck lists instead). An engine exception does not stop it: the game is recorded with its seeds, `termination` (`engine_error`, `decision_cap`, `time_cap`) and the exception text, and the JSON groups failures by text with numbers and card names normalised, fewest decisions first. It also lists games that hit the turn cap or ended without a winner or a reason, the longest 0.1% of games (a loop a cap hides is a defect too), and per-card coverage taken from engine events and the chain (in a deck / in play / triggered / activated / resolved). The process limits its own memory (`--memory-limit-gb`, default 4) so a game that grows without bound ends as `std::bad_alloc` instead of taking the machine; a game that ended that way is played again alone before it is reported. One game alone, with the last trace lines: `./build/deck_fuzz --replay <deckA> <deckB> <game seed> --trace --tail 30` (a deck is a seed or a deck list path; `--show-decks` prints the lists). Run it on the checked build too (`-DRIFTBOUND_CHECK_BOARD_INDEX=ON`, a build directory of its own). **Iterating** (fuzz, fix a batch, fuzz again with a fresh `--seed`): `--known docs/testing-known-failures.txt` (lines of `ID|text`) counts failures of a known cause apart from new ones and exits 1 only for a new one; `--max-chain N` (default 500) is where a self-feeding chain is stopped (`chain_runaway`, naming the card with most items), `--max-decisions` / `--max-seconds` the per-game caps; `--agents random-player` (or `--agent1` / `--agent2`) seats the agent that plays instead of passing, which reaches abilities plain random play rarely does; `--guide prev.json` weights deck building toward the cards the previous result exercised least (a seed then means a deck only together with that guide file: the replay command names it). `scripts/deck_fuzz_report.py result.json` prints a result as Markdown (totals, groups, the never-exercised lists); `scripts/deck_fuzz_compare.py old.json new.json [--min-resolved K]` says which failure signatures disappeared, which are new, and which cards gained or lost coverage. `tests/test_deck_fuzz.cpp` runs a few dozen games of it in the suite; a deck seed means the same deck until the card pool changes (`DeckFuzz.DeckOfSeedOneIsPinned`).

### Key Rule: Legends are NOT Champions
Legends (`card_type=legend`) and champion units (`card_type=unit, super_type=champion`) are fundamentally different. Never conflate them. They share champion tags but occupy different zones and follow different rules.

### Core principle: card mechanics are encapsulated in Card objects, not the engine

The GameEngine handles game flow (phases, turns, chain FEPR loop, cleanup, scoring) and provides atomic operations via EffectExecutor. All card-specific behavior lives in Card subclass `onResolve()` / `onTrigger()` / `onActivate()` overrides. **Never add card-specific logic to game_engine.cpp.** If you find yourself adding `if (card_name == "X")` or matching `ability_text.find("pattern")` in the engine, it belongs in the Card object.

## Architecture Notes

- **Card objects** (`src/cards/card.h`): Every card has a Card subclass registered in `CardRegistry`. Overrides `onResolve()`, `onTrigger()`, `onActivate()`, etc. All card-specific behavior — effects, targeting, countering, token creation, damage computation — belongs here, not in the engine.
- **CardRegistry** (`src/cards/card_registry.{h,cpp}`): Maps `CardDefId → Card*`. Loaded ONCE at application startup via `registerAllCards()` (aggregated in the checked-in `cards_init.cpp`, one hand-added line per card), shared as `const CardRegistry&` across all game threads. Card objects are stateless — concurrent reads safe. One authoritative class per card lives in its own TU under `src/cards/<type>/<id>_<slug>.cpp`.
- **Cards own their data** (single source of truth): each card class implements the pure-virtual `Card::def()` returning its `CardDef` (a `const CardDef def_` member). `CardDB::buildFromClasses()` materializes the card table by asking every registered card for `def()`. There is NO `registry.json` and NO code generation — cards are hand-authored C++. Tournament legality is class-owned too (`CardDef::banned`); there is no `ban-list.csv`. The CLI `--dump-registry <path>` exports the compiled card table to registry-style JSON for external/validation use.
- **Object table and board index** (`core/object_table.h`): `GameState::objects` is an `ObjectTable` — the `unordered_map<GameObjectId, GameObject>` it always was (same iteration order, stable references) plus lists of the objects in play: `objects.onBoard()` (everything with a location), `objects.inPlay()` (the board and the Legend Zones), `objects.atLocation(loc)`. They iterate like the table (`for (auto& [id, obj] : state.objects.onBoard())`), in the table's order, so a walk over every object that skipped what is not on the board becomes a walk over the board by naming the range. `GameState::unitsAt` / `objectsAt` / `allUnitsControlledBy` / `runesInBase`, `boardObjects`, `chooseableUnits` and the `resource::` counters read them. **Nothing maintains the index by hand**: `GameObject::zone` and `GameObject::location` are tracked fields (`core/tracked_field.h`) that read as a `ZoneType` / `std::optional<LocationId>`; assigning either marks the table's lists stale and the next query rebuilds them. A location is replaced, never edited in place (`*obj.location` is const), and a cast of a zone needs `obj.zone.get()`. Use a range only for a loop whose body cannot move an object; a loop that kills, moves, plays or creates objects collects ids first, as before. `-DRIFTBOUND_CHECK_BOARD_INDEX=ON` builds a slow variant in which every query recomputes the lists and compares, and a loop that moves objects under a range throws: run the suite with it after touching the table or converting a loop. A `const GameState` may be queried from several threads at once (the rebuild is guarded: an atomic flag, a mutex only around the rebuild); writing to a state another thread reads is not safe, as for any other data.
- **Card facts that need no game state**: `Card::firesOn(trigger)` and `Card::abilities()` (the card's `activatedAbilities()`, as a reference) answer from data built once per card object when the card is registered (`Card::primeStaticFacts`). Engine code reads those; a card still declares itself through `triggerTypes()` / `activatedAbilities()`, which must not depend on anything but the card class. `CardRegistry::get` is a table lookup by id.
- **EffectExecutor**: Utility library of atomic game operations (`dealDamage`, `drawCards`, `killObject`, `bounceToHand`, `createToken`, `copyUnit`, `predict`, `moveToBattlefield`, …). Card objects call these via `ctx.executor.*`. The executor does not decide WHAT to do — that's the card's job.
- **Leaving the board makes a new object (CR 124.1)**: every path that takes an object off the board ends in `EffectExecutor::leftBoard(id)`, which sheds its attachments and calls `forgetBoardState` (`core/board_state.h`): Stunned, Exhausted, Empowered, damage, buffs, the combat designation, "this turn" Might and keywords, control changes (off the board a card is its owner's) and continuous-effect leftovers are dropped AT THE MOVE, after the move's events are out; the card has its printed keywords and Might again. Kept: `last_known` / `last_location` (what "When I die" abilities read), `card_counters` / `string_state` / `tracked_objects` (the cards' own memory), identity. The paths: `killObject` (unit, gear), `GameEngine::killUnit`, `bounceToHand`, `banishObject`, `replaceBattlefieldWithToken` / `restoreReplacedBattlefield`, `recycleCards`, `putIntoDeckFromBoard`, the recycle-self activation cost, a rune recycled for Power (`resource::pay`, `payCardCost`, the effect-play cost), and the state editor. **A card never writes `zone` / `location` to take something off the board**: it calls one of those. **Reading a card after it has left**: every one of those paths first takes `GameObject::last_known` (`EffectExecutor::snapshotLastKnown`: controller, Might, buffs, Stunned, attachments, keywords, location, `died`) and makes all its announcements before the object is reset. Code that runs after the move ("its controller draws", "its Might", "there", a "When I die" ability, another unit's death ability) reads `last_known` — `controllerWhenItLeft` (`card_helpers.h`) for the controller, which for a unit taken from its owner is not the owner (CR 359.3.e.13) — never the live fields. Units that die together are snapshotted before the first is killed (`DeathBatch`), and none of them triggers on another's death (CR 383.2.c.2: `endDeathBatch` takes those abilities back off the chain). The snapshot of the object whose leaving triggered an ability travels with the chain item (`ChainItem::subject_as_it_left`): a resolving ability reads it with `asItLeft(ctx, id)` / `controllerWhenItLeft(ctx, id)`, so a card that dies twice has each death ability read its own death. **A death batch must know who dies before the first kill**, because what replaces any of the deaths is applied first with all of them on the board (CR 373.1.a, 370.4): `DeathBatch(executor, units)` when every listed unit is killed; a card that deals damage and then kills what that killed calls `ctx.executor.killLethallyDamagedTogether(units)` and writes no loop of its own (it asks `EffectExecutor::damageKills`, the cleanup's test, Elder Dragon's rule included). A replaced member's `killObject` does nothing while the batch is open, and when several of one player's dying units could each have their death replaced, that player is asked which goes first (CR 373). The checked build (`-DRIFTBOUND_CHECK_BOARD_INDEX=ON`) throws in `recalculateAuras` when, in a game the engine plays, an off-board object still carries board state (`carriesBoardState`). **Board state is written only to an object in play**: the executor's writers (`giveTemporaryMight`, `giveTemporaryKeyword`, `exhaustObject`, `takeControl*`, like `dealDamage`, `buffUnit`, `stunUnit`, `readyObject`, `empower` before them) do nothing for an object that is not on the board (or a legend / battlefield card in its zone), so an ability that resolves after its source or target has left writes nothing to the card in the trash or hand. A card that writes a field itself (`obj.keywords.set`, a `card_counters` mark that an aura reads) checks `location.has_value()` first.
- **Move vs recall (CR 421, 457-460)**: `EffectExecutor::moveToBase` is a MOVE — it counts toward `moves_this_turn`, emits `UnitMovedEvent` and is refused where a move is blocked (`moveToBaseBlocked`, `cant_be_moved_by_enemy`). "Recall it" is `EffectExecutor::recallToBase`: not a move (no count, no move triggers, not stoppable by movement restrictions, CR 458), the permanent keeps its damage and statuses and its attachments go with it (CR 719.3.a); it emits `ObjectStateChangedEvent "recalled"`. A replaced death ("heal it, exhaust it, and recall it") is `healExhaustRecall`; both kill paths ask `applyOwnDeathReplacement` first.
- **One attach path**: every attach — Equip, Weaponmaster, Quick-Draw, `attachEquipped` / `attachFree` in `card_helpers.h` — ends in `EffectExecutor::attachGear(gear, unit)`: both must be on the board (CR 716), a gear attached elsewhere comes off first (`unattachGear`, its `onUnattached` runs), and the gear's printed rules text goes Inactive (`is_rules_text_inactive`, CR 718.2). Cards do not write `attached_to` / `attachments` themselves.
- **Tokens are played (CR 350.2)**: `EffectExecutor::createToken` emits `TokenCreatedEvent`, which drives "When you play a unit / a gear" watchers and the token's own keyword abilities. A token that is a registered token card (Gold, Shadow Clone) is created with the `token_card` argument so its card is set before the play is announced. When the instruction lets the controller choose where the token goes, the choices are passed as `location_choices` so an additional copy ("play that token and an additional copy of it") is given the same choice.
- **Draws by an effect that already holds the card** ("look at the top two, draw one"): `EffectExecutor::drawHeldCard(player, card, seen_by_all)` — it counts as a draw (`draws_this_turn`, `CardsDrawnEvent`). Putting a card into a hand with `hand.push_back` is right only when the text says "put it into your hand", which is not a draw.
- **Spending a buff (CR 427.2)**: `EffectExecutor::spendBuff(unit, spender)` — emits `"buff_spent"` → `WhenYouSpendABuff`, credited to the player who spent it.
- **Keyword abilities** (`engine/keyword_abilities.{h,cpp}`): [Vision] (CR 817), [Weaponmaster] (CR 821) and [Temporary] (CR 816: queued by `TriggerManager::queueTemporaryAbilities` for the turn player's permanents as the Beginning Phase is announced, in one batch with the "start of your Beginning Phase" abilities; it kills its source if that has not left the board since — `ChainItem::source_left_board`; resolved with its Cleanups before the Scoring Step) are triggered abilities of the KEYWORD. A permanent can have the keyword from a continuous effect and may be a token with no card class, so `TriggerManager::queueKeywordAbilities` queues a chain item with `ChainItem::keyword_ability` set and resolution dispatches to the stateless object `keywordAbilityCard(keyword)` returns. Each instance triggers separately (`keywordAbilityInstances`, CR 817.2).
- **Text-copying Equipment** (Svellsongur, CR 479.1.d): a gear that overrides `Card::copiesBearerText()` gives its bearer each of the bearer's abilities once more per such gear — `EffectExecutor::textCopiesOn(unit)` counts them, `TriggerManager::fireTrigger` queues the bearer's triggered abilities that many more times and `recalculateAuras` applies its continuous effects that many more times.
- **Units that die together** ("if I didn't die alone", "when one or more enemy units die"): each dying unit's `GameObject::last_known` (location, the other friendly units there, keywords, who killed it — `killed_by`) is taken while all of them are still on the board. Lethal damage found in one cleanup is one batch; a card that kills several units in one effect declares a `DeathBatch` guard (`effect_executor.h`) in a block of its own with the kill loop, so the batch ends with the kills. `Card::triggersOncePerBatch(trigger)` makes a watcher fire once for the set.
- **`StateSettledEvent`** is emitted by `GameEngine::cleanup` once continuous effects, Might and control are final for the current state. `TriggerManager::onStateSettled` uses it for triggers that watch a computed value cross a line: `Card::mightThreshold()` → `WhenMyMightReachesThreshold`.
- **Extra score triggers** ("hold / conquer effects here trigger an additional time"): `Card::extraScoreTriggers`, read by `TriggerManager::onScore`.
- **TriggerManager** subscribes to `EventBus` and, for each event, queues the ability of every card that fires on it (`Card::firesOn`, i.e. `triggerTypes()`; the single `triggerType()` is the back-compat default) through `fireTrigger`, which applies `Card::triggerCondition` — **the place for every conditional statement that follows the trigger condition** ("..., if I'm at a battlefield", "while I'm ...", "the third time", "once each turn" with `triggeredAbilityOnChain`, "from face down", "on an opponent's turn"): CR 383.2.a.1, judged when the event happens and not again as the ability resolves — and records the event's object as `ChainItem::triggering_subject` (and, for a move, its origin and destination as `ChainItem::triggering_move`). `checkDelayedAbilities` does the same for the `DelayedAbility` list.
- **Delayed abilities** (`GameState::delayed_abilities`): one-shot by default (`fired`), or firing on every matching event until they expire (`repeats`). `expires_on_turn` defaults to `DelayedAbility::kThisTurn` — an ability nobody dated ends with the turn it was made in; `kUntilFired` never expires; otherwise it is removed by the Expiration Step of that turn number.
- **Chain is a LIFO stack** (`std::vector`, resolve from back). When a spell/ability resolves, FEPR pops it then calls `resolveSpell()` which dispatches to `card->onResolve()`. Counter spells use **peek-and-pop**: the counter resolves (popped by FEPR), then pops the next spell. Counter-of-counter works naturally via LIFO — no flags, no scanning, no chain mutation outside the card's own `onResolve`.
- **The chain's loop is HOT FEPR (CR 334)** (`ChainManager::processFEPR`): handle outstanding tasks — `GameEngine::cleanup`, injected — then finalize the OLDEST pending item, or give priority, or resolve the newest item; one step per pass, **a Cleanup after every step** (CR 319.3-319.5: before the first finalization, after each finalization, after each resolution; skipped only after a finalization that chose, paid and logged nothing). So lethal damage is killed, unattached gear recalled, continuous effects and Might recomputed, "becomes [Mighty]" noticed and a win declared between the items of a chain, and whatever that triggers is pending for the next pass. **Two shortcuts keep the ~270 Cleanups of a game cheap, on only in a game the engine plays (`playing_a_game_`)** (note above `GameEngine::cleanup`): (1) once a full Cleanup finds every object in a Main Deck / Rune Deck / Trash / Banishment inert (`inertInAPile`), Cleanups walk `ObjectTable::offPiles()` only; a card whose continuous effect is given to cards in the piles declares `Card::continuousEffectReachesPiles()` (Jax, Unmatched) and every object is walked while it is in play; (2) a Cleanup that follows one that changed nothing is not run when `EventBus::activity()` (every emit and every log line, heard or not) and `cleanupShape()` are unchanged. `mutableState()`, a resumed snapshot and the probes' state swaps forget both. The checked build never skips: it runs the Cleanup it would have skipped and throws on any change, announcement or feature-vector difference, and throws when a pile object is not inert after a reduced pass. `deck_fuzz --rows` writes one line per game, to show two builds play the same games. The loop ends only when a Cleanup leaves the chain empty: `GameEngine::runChain()` is "settle everything" and replaces every `runChain(); cleanup();` pair — it is called after an intent, at the end of every phase function, in the Expiration Step after its body (CR 317.2), after a showdown's start and after each showdown action. The state is Closed while a chain exists (the loop writes it) and Open for the Cleanup after the last resolution (CR 323.5). A nested call does nothing (a card played in response; an item mid-resolution, CR 321). **A hand-set state does not survive the engine path**: a Cleanup runs before anything is finalized, so a test's combat designation needs a combat in progress (`CardTestFixture::combatInProgress`), a controlled battlefield needs a unit, a facedown card needs its battlefield controlled.
- **A triggered ability that is not performed leaves the chain as it would be finalized** (CR 403.1.a, 403.4, 405.2; `GameEngine::runFinalizePass` sets `ChainItem::remove_at_finalize`): its leading "may" was declined or not offered (`may_answer == 0`), or a choice helper found no legal option for a REQUIRED choice (`Card::requiredChoiceMissing`: `pickTarget`, `pickTargetPair`, `pickMode`, `splitDamageAmong` without `may_choose_none`). No finalized event, no priority; alone on the chain it leaves an Open State. Not a spell, not an activated ability, not a mistarget. A card whose `confirmOptional` is an optional PART of its effect ("heal ..., then move up to one") calls `Card::mayIsNotTheWholeAbility(ctx)` first and stays. `SweepCostsTest.Removal_NoRegisteredTriggerLosesAnEffectExceptTheListedOnes` runs every opted-in trigger with the removal on and off; a card it reports either needs that call or is a strict-403.4 case for the list (Teemo, Strategist; judge question 6).
- **Simultaneous triggers are ordered by their controllers (CR 383.3.d)**: `TriggerManager` stamps every triggered item with `ChainItem::trigger_batch` — one batch per event it handles (`TriggerEventScope`), or one the engine holds open across events the rules call simultaneous (`SimultaneousTriggers`: a death batch, the units one Cleanup finds newly Mighty, a combat's start with its showdown's start, the units that join a combat in one Cleanup). Before a batch's first item is finalized `GameEngine::orderPendingTriggers` puts the turn player's items lowest (the attacker's in a combat-start batch, CR 466.2.d.1) and asks a player with two or more DIFFERENT abilities for the order: a `MakeChoice` per position but the last, `chosen_value` = index, label "Order — <source> ...", first option = the order queued. Reflexive triggers and items an effect queues (`queueTriggeredAbility`) are in no batch. The test fixture answers order prompts with the first option and keeps them in `EnginePathAgent::order_prompts` (`order_pick` to choose).
- **A permanent's play (CR 354-359, 383.4.a.2)**: `executePlayCard` decides [Accelerate] (`decideAccelerate`: asked before anything is paid, only if cost plus [1][C] is payable, paid in the one `payCardCost`) and the card's optional additional cost (`maybePayOptionalAdditionalCost`, tried on a parked copy of the game so it is offered only if the card stays payable) before the cost; the permanent's chain item goes BELOW whatever paying for it triggered (`placeBelowWhatItsPlayTriggered`, spells too: a Deathknell from a spell's additional cost resolves before the spell); and the play is announced — `CardPlayedEvent`, "played not from hand", so every play trigger — by `resolvePermanent` once the card is on the board (`announcePermanentPlayed`).
- **Combat triggers follow the designation (CR 383.4.e/f)**: `TriggerManager::fireAttackDefendTriggers` fires a unit's WhenIAttack / WhenIDefend / WhenIAttackOrDefend (own and equipped) once per combat (`__attack_defend_checked`), at `CombatStartedEvent` for the units there and at `ObjectStateChangedEvent "joined_combat"` — announced by `processContestedBattlefields` when a Cleanup gives a late arrival its designation (CR 466.2.c.3.a). `runCombat` also emits `ShowdownStartedEvent` (CR 466.2.b).
- **Loops (Tournament Rules 505)**: a triggered ability's leading "may" is not offered once it has been accepted `ChainState::kMayLoopIterations` (100) times in one unbroken chain (505.4 / 505.7 / 505.10: a loop kept going by decisions runs for a number of iterations, then that player decides otherwise; `Card::confirmOptional`, counts in `ChainState::may_loop_counts`). A chain that reaches the loop's bound with no card prompt answered in the whole run is a loop of mandatory actions nobody broke: the game is a draw with that stated reason (505.6). Reached otherwise the bound is an engine error.
- **Aura system** uses tagged effects (`AuraEffect` on GameObject), recalculated from scratch during `cleanup()`. No formal layer system. `hasKeyword()` checks both base and aura-granted keywords. **`Card::applyPassiveAura` is called ONCE per (card, controller)** that has an instance in play (board or Legend Zone), not once per instance and without saying which instance: the hook must loop over every instance that controller has (or use `forEachSelfOnce` in `card_helpers.h`), check each one's own condition and let copies stack. A battlefield card is called once per battlefield slot holding it. It is the only way a card has a continuous effect: the engine does not read aura wording out of `ability_text`. A keyword granted "if they didn't already" (Spirit's Refuge) is pushed with `auraKeywordIfAbsent` (`AuraEffect::only_if_absent`): `recalculateAuras` drops it, after every `applyPassiveAura` and `applyMightDependentAura` hook of the pass has run, from an object that has the keyword from any other source, so the result does not depend on hook order.
- **Combat damage**: Both attacker and defender queried through the agent interface. Tank/Backline ordering enforced. Agent picks from greedy-lethal, spread-even, focus-all, and lethal-first distributions. The attacker assigns, then the defender, and only then is all of it dealt, in one trigger batch (CR 467.2.c.1.a): the defender assigns with no combat damage dealt and nothing it triggers pending.
- **A combat is a Showdown State (CR 308.1)**: `runCombat` sets `ns_state = Showdown` until `combatResolutionStep` ends it, so at its Focus (and in its chain windows) only [Action] / [Reaction] cards and abilities, [Ambush] units and hidden cards are offered, to either player, Flow replays included. Control of an empty battlefield is lost in any Open State with no showdown or combat there (CR 323.5), Showdown Open included. **Focus starts** with the Attacker in a combat (CR 466.2.c.1.a) and with the player who applied Contested — the controller of the unit that applied it — in a non-combat showdown (CR 345; judge question 8), not with the turn player.
- **Scoring Step**: every battlefield the turn player controls is held (one `SimultaneousTriggers` batch), then one `runChain` (CR 315.2.b.2); a hold that wins ends the step. **Between combats**: what establishing control queued resolves inside `combatResolutionStep` (CR 468.6) and what a showdown's end queued in `advanceMainPhase` before the next battlefield's showdown or combat begins (CR 323.11 / 323.12).
- **Cost payment**: `payCardCost()` applies `CostModifier` reductions, then exhausts runes for energy (agent-chosen), then recycles runes for power (agent-chosen). Energy-first ordering allows recycling just-exhausted runes for power. Each rune selection is an agent decision point. Every other payment (Equip, activated abilities, Accelerate, Repeat, Hide, Flow and trash-play grants, Deflect) goes through `engine/resource_payment.h` (`resource::canPay` / `resource::pay`), which takes a `SpendFor` purpose.
- **Deflect paid ahead of a spell's cost**: a spell that makes its choices before it is paid for (a play-time target, a `kFinalizeResolve` pass) pays a chosen unit's Deflect as the choice is made, before its own cost. `EffectExecutor::payAnyPower` then pays through `resource::payAnyPowerAheadOfCost`: it takes what the spell's own Power cannot use first (floating Power and runes of other Domains) and exhausts a ready rune for its Energy before recycling it, so what is left still pays the cost — the same joint payment `GameEngine::canAffordWith` judged the offer by. `DeflectBeforeCost.NoRegisteredSpellThatChoosesBeforeItsCostIsLeftUnpayableByADeflect` plays every such spell from runes alone against units with [Deflect]; a sweep that funds plays with floating Energy and Power does not exercise which rune is recycled.
- **Restricted resources**: `RunePool::unit_energy`, `spell_energy`, `showdown_energy`, `spell_power`, `gear_power` hold resources a card restricts ("Use only to play spells"). They are spent before unrestricted ones and only for the matching `SpendFor` (showdown Energy only while a showdown or combat is under way); a card adds to the pool field directly.
- **Additional costs chosen before payment (CR 356.2)**: "As an additional cost to play me, kill a friendly unit", "you may spend a buff ... ignore this spell's cost", "you may discard 1 ... reduce my cost by [2]" are `Card::additionalPlayCost()` (what the play gate sees: exists / mandatory / payable / best discount) and `Card::payAdditionalPlayCost(ctx, affordable)` (asks with `ctx.executor.confirmNow` / `chooseObjectNow`, pays, returns the `PlayCostAdjust`). The engine calls it after the card left its zone and before its cost is paid, on every play path (hand, reaction, effect plays that pay). An optional cost may be declined only while the card is affordable without it. A card that needs to remember it was paid sets a `card_counters` flag for its play trigger's `triggerCondition`.
- **Equip (CR 818)**: a gear declares its Equip cost as data — `Card::equipCost()` (Energy / Power) plus `canPayEquipExtraCost` / `payEquipExtraCost` for the non-resource part ("Spend 1 XP", "Kill a friendly unit") and `onEquipped` for what happens on attach. `Card::canPayEquip` is the one gate (generator, execution, Weaponmaster) and `Card::payEquipAndAttach` the one payment; `EquipTerms` carries discounts (first gear ability each turn, Weaponmaster's "[A] less" and "even if it's already attached"). An attached Equipment's own Equip is not offered (its Rules Text is Inactive, CR 718.2).
- **Weaponmaster (CR 821)**: `WeaponmasterUnit` (`cards/units/weaponmaster_base.h`) asks the may and the Equipment and pays the Equip cost one Power less through `weaponmasterChoices` / `weaponmasterEquip`. A permanent that has the keyword from a continuous effect (a Sand Soldier token) gets the same ability through `engine/keyword_abilities`.
- **Repeat (CR 820)**: a card declares `Card::repeatCosts()` (one entry per printed cost; Energy, Power, or a discard). `executePlaySpell` offers each once after the base cost is paid. **Spells only**: CR 820.1.a also allows [Repeat] on an ability, but no card prints one and the engine has no path for it (only `executePlaySpell` offers the cost). `VerifyEngineTest.Registry_OnlySpellsDeclareRepeatCosts` fails when a non-spell card overrides `repeatCosts()`, so the gap cannot be met silently: add the ability path with that card.
- **A spell's choices come before its cost (CR 355 -> 356)**: a play-time target (`needsPlayTimeTarget`) and the whole finalize pass of a `kFinalizeResolve` spell are made in `executePlaySpell` before `payCardCost`, so a discount from what is chosen counts and each choice's Deflect is judged together with the cost (`EffectExecutor::setChoiceFilter` limits the helpers to objects that leave the spell payable). The result is adopted when the spell goes on the chain. Prompt order is therefore: the spell's choices, then cost prompts (additional costs, Repeat). The generators agree through `canAffordChoosing` and, for a finalize-pass spell too dear on its own, `Card::mayChooseAtFinalization`.
- **A play offered through a discount cannot end unpaid**: a finalize-pass spell that is too dear on its own is offered only if some complete sequence of its choices makes it payable. `payableThroughAFinalizeChoice` first asks the card's declaration (`Card::mayChooseAtFinalization`, declared by every such spell and checked against its real pick list by `SweepCostsTest.FinalizePassSpellDeclarationsMatchTheirPickLists`), then makes the choices on the side (`prePlayProbe`: nothing seen or kept — `EventBus::beginQuiet`; the game is moved aside and the probe plays on a copy, one `GameState` copy per run). The probe walks at most `kPrePlayProbeRuns` (256) sequences, trying first the answers that name an object with which the spell is payable there and then (no registered spell needs more than 3 runs on any board: `SweepCostsTest.FinalizePassSpell_NoRegisteredSpellComesNearTheProbeBound`); reaching that with sequences left and none payable throws a `std::logic_error` naming the card (the answer is unknown, and "not offered" would withhold a play), and so does a contract error of the card's pass met inside the probe. In the real pass of such a spell only the options a payable sequence can still follow are put to the player (`choosePrePlayViable`). Both rely on a finalize pass being **repeatable**: from the same state with the same answers it asks the same prompts — so a card keeps nothing that steers its prompts outside the `GameState` and its chain item (`choosePrePlayViable` throws, naming the card, when a pass is not).
- **Card contracts the engine checks as it runs**: a cost paid and then a prompt before the marker in a finalize pass (error); a prompt option with no value, object or `chosen_card_def`, or equal to another (error, `GameEngine::askAgent`); a finalize pass that ends anywhere but where the rule below allows (error, `GameEngine::runFinalizePass`); a pre-play probe that reaches its bound without an answer (error, see the bullet above). All are `std::logic_error`s naming the card, in the probe as in the real pass. `SweepCostsTest.CardContract_NoRegisteredCardEndsItsFinalizePassAnywhereElse` runs every opted-in card's spell plays, trigger types and activations on two boards.
- **Where a finalize pass may end** (the rule, also at `Card::finalizingChoices`): (1) at the marker, `if (finalizingChoices(ctx)) return;`, or (2) at a return taken because a choice helper stored "nothing to decide" on the chain item — `confirmOptional` 0 (declined, or its `still_legal` false), `pickMode` -2, `pickTarget` / `pickTargetPair` / `selectObject` `kInvalidId`, `splitDamageAmong` with nothing to target. Those are safe because the resolution gets the same stored answer and asks nothing. Any other return before the marker — a test of the card's own on a counter, the event's subject, a "paid" flag — is an error: nothing was stored, so the resolution would run the choices afresh. Write such a test INTO the helper instead: pass an empty pick list, or make `still_legal` false, and return after the marker.
- **Per-play payment flags**: a card that must remember its additional cost was paid sets `card_counters[Card::kAdditionalCostPaid]`; `Card::forgetPlayPayments` clears it (and any `OptionalAdditionalCost::paid_flag`) as every play begins.
- **Other cost hooks**: `Card::trashPlayCost()` (a standing "play me from your trash for ..." permission), `Card::adjustHideCost()` (Hide cost changes), `Card::optionalCostDiscount()` ("optional additional costs you pay cost [1] or [A] less"), `Card::activationPowerReductionFor()` (the "[A] less" half of an activation discount).
- **Multi-ability per Card**: `Card::activatedAbilities() → vector<ActivatedAbility>` returns N descriptors. Default impl wraps the legacy single-ability virtuals for back-compat. Multi-ability cards override `activatedAbilities()` and override the indexed `onActivate(ctx, ability_index, targets)`. `Intent::ability_index` + `ChainItem::ability_index` carry the choice through.
- **Agent answers are checked**: every decision of a game — main phase, priority, showdown, mulligan, combat damage, a rune pick, a card's prompt — is asked in one place, `GameEngine::askAgent`, and the answer must be one of the options offered (`Intent::operator==`). Anything else is a caller error: `std::invalid_argument`, nothing executed, nothing recorded in `action_history` (the step API's `applyChoice` takes an index, so it cannot produce one; it throws `std::out_of_range` for a bad index). Concede is always accepted. Cards therefore never see an answer they did not offer. `testHook_executeIntent` bypasses decisions: a test that hand-builds an intent is responsible for it being legal.
- **State edits during a decision**: `GameEngine::mutableState()` taken while the engine waits on an answer (the play server's god mode) counts as an edit of the position the options were built for. The answer is then held to the edited state: for the three decisions the engine can rebuild (`recomputePendingLegalActions`: main phase, showdown focus, chain priority) it must be in the rebuilt list; for any other it must be an offered option that names no object the edit moved, removed or gave to another player. A stale answer is refused like an unoffered one.
- **Costs that could not be paid**: "kill X to do Y" pays with `Card::killAsCost(ctx, object)`, which is true only if the object DIED (a death replaced by anything — it stayed, was recalled, was banished "instead" — is not a kill). A failed attempt is recorded on the chain item (`Card::markCostUnpaid` / `costUnpaid`), so the finalize pass and the resolution agree and the cost is attempted once.
- **Lists a card offers**: build them with `boardObjects(state, pred)` or `chooseableUnits(state, chooser, pred)` (`card_helpers.h`). Both return ascending object ids, so option order is a property of the helper, not of the hash order of `GameState::objects`. Several picks, one prompt each ("up to N", "any number of") are `selectSeveral`, which composes with the `pick*` helpers and has no cap of its own.
- **Split damage (CR 355.14)**: `splitDamageAmong` asks WHO first — each unit is a target, chosen as the item is finalized ("No more targets" is offered first from the second prompt on; Deflect is paid and the unit counts as chosen then) — and HOW MUCH as it resolves (1 each, then one point per prompt). The card opts into `kFinalizeResolve` / `kFinalizeTrigger`; the helper is its end-of-choices marker. For "any number of" / "up to" text pass `may_choose_none`: the first prompt then also offers "No more targets", after the units (CR 355.13).
- **Cost modifiers by play source**: `CostModifier::from_hand_only` limits a modifier to a card played from a hand ("you may play a gear from hand ... ignoring its Energy cost"); a play from the trash, the Champion Zone or by an effect from elsewhere neither gets it nor uses a one-shot up (`PlayerState::current_play_source`).
- **Resumable agent choices**: `Card::confirmOptional` (yes/no), `Card::pickMode` (modal), `Card::pickXAmount` (variable-X), `Card::pickTarget` (single), `Card::pickTargetPair` (dual). They compose **in any order** within one callback: each helper tracks its own waiting/answered state (flags in `resume_data[Card::kChoiceStateSlot]`; `confirmOptional` uses `ChainItem::may_answer`), not the shared `resume_point`. One call of each helper per callback (a second `confirmOptional` / `pickTarget` returns the first answer). `resume_point` is still written so a card can tell a suspend from a fizzle:
  - confirmOptional / pickXAmount: 1 waiting, 2 answered (X in resume_data[0])
  - pickMode: 4 waiting, 5 answered (resume_data[1])
  - pickTarget: 7 waiting, 8 answered (resume_data[2])
  - pickTargetPair: 10 / 12 waiting (returns `{kInvalidId, kInvalidId}` for both), 13 done (resume_data[3..4])
- **Choices at finalization (CR 355, 383.3)**: a triggered ability's "you may", its "[cost] to [effect]" payment and its targets are decided when it is finalized, not when it resolves. A card opts a callback in with `choicesAtFinalization()` (`kFinalizeTrigger` / `kFinalizeResolve` / `kFinalizeActivate`); the engine then runs that callback once at finalization (`GameEngine::runFinalizePass`) and again at resolution, where the choice helpers return the stored answers. The card marks the end of its choices with `if (finalizingChoices(ctx)) return;` — **nothing before that line may change game state** except the helpers and costs guarded by `costDueNow(ctx)`; pre-checks that depend on the cost use `costAlreadyPaid(ctx)`. The marker also ends the cost section when no finalize pass ran: a cost `costDueNow` reported as due counts as paid once a run of the callback reaches the marker, so it is due exactly once per chain item however often a later prompt re-enters the card. Inside a finalize pass the engine enforces the order: a card that pays under `costDueNow` and then asks for a choice before its marker makes `runFinalizePass` throw a `std::logic_error` naming it. Every branch of a multi-trigger card needs the marker, including branches with no choice. A target chosen at finalization that is no longer legal at resolution comes back as `kInvalidId` (mistarget). **The engine never passes targets to `onTrigger` / `onEquippedTrigger`** (the `targets` argument is always empty; the event's subject is `ChainItem::triggering_subject`): a triggered ability that needs a target opts in with `kFinalizeTrigger` and picks it with `pickTarget` / `pickTargetPair` from a list it builds itself. Finalization is wherever the rules finalize, not only the chain's Finalize step: a spell an effect plays makes its choices as it is put on the chain (`setQueueSpell`), an item told to "make new choices" makes them at once (`makeNewChoicesFor`), and each [Repeat] execution's choices are made with the first one's and kept in `ChainItem::repeat_choices` (CR 820.2); `runFinalizePass` sets an item that is mid-resolution aside while it runs.
- **Play-time targets**: `Card::needsPlayTimeTarget()` (single target) and `Card::needsPlayTimeTargetPair()` (dual) opt the action generator into emitting ONE `Play` intent per card (no per-target variants), so each target choice is a prompt whose options have slots of their own instead of being twins of one Play slot. The card's `onResolve` uses `pickTarget` / `pickTargetPair` at chain time. Equivalent for activated abilities: `ActivatedAbility::needs_activation_time_target`.
- **Action ids (OpenSpiel)** (`openspiel/action_vocab.h`): `id = slot + kNumSlots * twin`. The **slot** (`actionSlot(intent, state)`, 127,124 of them) says what the action is made of — verb plus key: (card, where, how) for a play, (unit card, destination) for a Standard Move, the hand positions of a mulligan, the decider's or the opponent's card for a prompt's object, the number for a prompt's value; a card-keyed range has key 0 for an object with no card id. The **twin** number tells apart the legal intents of one decision that share a slot (two copies of a card, a spell offered once per target), numbered in the canonical order `compareIntents` (field by field, objects by id), which depends neither on the generator's order nor on anything the deciding player cannot know. `actionIds(legal, state)` gives the id of every intent of a legal list: **no two distinct legal intents share an id and every legal intent has one** (`tests/test_action_ids.cpp` walks every decision of 146 random games, the whole card pool included; keep it green). `NumDistinctActions` = `kNumActions` = `kNumSlots * kTwinPlanes` (1024), a fixed number; past the planes `RiftboundState::LegalActions` throws rather than drop an option. A twin number means "another action with this description", not the same object across positions.
- **Action history and replay (OpenSpiel)**: `GameState::action_history` holds one **history token** per applied decision (`openspiel::historyToken`): the intent's slot plus a fingerprint of the whole Intent (object ids included), which is what identifies it in its legal list. Replay matches tokens (`findHistoryToken`). A token does not hold the twin number (working it out for every decision cost 4% of random play); `RiftboundState::actionHistory()` therefore returns slots, and the ids of a game driven through `ApplyAction` are OpenSpiel's `History()`. `RiftboundState::Clone()` is lazy: a clone taken at a top-level main-phase decision (`GameEngine::isResumableDecision`) resumes straight from the snapshot; a clone taken anywhere else (mulligan, chain priority, showdown, combat, cost payment, a play-time prompt) is rebuilt from the nearest resumable ancestor by replaying the tokens since, and the rebuilt engine is checked against the snapshot's pending decision (a mismatch throws). `MctsAgent` keeps a mirror state built from the same decks and engine seed and syncs it with `RiftboundState::syncToHistory`.
- **`random-player`** (`agents/random_player_agent.h`; `--agent1 random-player`, beside random, mcts, ismcts, human): uniform over the legal actions that are NOT a pass. When it could act it passes with probability P (`random-player:pass=P`; **default 0.2**); `random-player:pass=0` is forced play, which never passes while anything else is legal; it always passes when a pass is all there is. Seeded like the random agent (same seed, same game). A pass is told from the Intent's fields, never from a label (`isPassOption`): PassPriority, PassFocus, EndTurn, DeclineOptionalTrigger, DeclineTriggeredCost, a mulligan that sets nothing aside, and in a prompt the option that names nothing and carries value 0 when the prompt also offers an object or a named card ("None", "No more targets", "Move no more units", "Keep it") or when whoever asked marked it as the decline of a yes/no (`Intent::declines`: the "No" of `Card::confirmOptional` and `EffectExecutor::confirmNow`, of an [Accelerate] / [Repeat] / triggered cost, of a yes/no a card builds with `declineChoice`). The values alone say nothing: two modes, an X of 0 or 1 and "cost [1] less / [A] less" are the values 0 and 1 too, and with pass=0 both of their options are taken. `Intent::declines` is not part of the answer (not in `operator==`, the action id or the history token). A card that builds a yes/no by hand must use `declineChoice` for the "no", or forced play treats it as a first mode.
- **Search agents** (`agents/mcts_agent.cpp`): `MctsAgent` wraps OpenSpiel's `MCTSBot` (PUCT, priors from `RiftboundHeuristicEvaluator::Prior`); `IsMctsAgent` runs `IsMctsSearch`, the algorithm of OpenSpiel's `ISMCTSBot` on ordered containers. Both score a leaf with the score-difference heuristic, keep a mirror of the live game (`LiveMirror`) and must be given the live engine's seed; if the live game cannot be reproduced from its history they answer uniformly at random at every decision that is not a top-level main-phase one. **A search agent's game is a function of its seeds** (`IsMctsAgentTest` / `MctsAgentTest.TheSameSeedsPlayTheSameGame`): do not iterate an absl hash map (or any container whose order depends on addresses) where the order can reach a choice — that is why `ISMCTSBot` itself is not used.
- **Target roles**: `targets` as handed to `onResolve` / `onActivate` holds only the play-time targets that are still legal, in chosen order with the gaps closed — positions are not roles. A card whose slots mean different things reads each one with `Card::chosenTarget(ctx, targets, role)` (kInvalidId once that slot's target is illegal).
- **Target legality at offer time**: the generators call `Card::hasLegalTargets(state, controller, card_db)`; override that overload when the requirement is on a printed value (Defy, Rebuttal), the two-argument one otherwise. The default requires a whole legal choice for a fixed-count multi-target spell.
- **Play locations**: a unit's printed permission is `Card::extraPlayLocations()` (`kPlayToOpenBattlefield` / `kPlayToOccupiedEnemyBattlefield` / `kPlayToLoneEnemyBattlefield`), a grant to other units is a `PlayerState` flag set from `applyPassiveAura` (`grant_friendly_units_open_bf`, `grant_units_lone_enemy_bf`); both are read in one place, `GameEngine::unitPlayableAt`. A battlefield's "can't be played here" / "can't move from here to base" are `BattlefieldCard::blocksUnitPlay()` / `blocksMoveToBase()`. Where an EFFECT plays a unit or a unit token is `playLocations` / `tokenPlayDests` / `playTokensChoosingLocations` in `card_helpers.h`; all of them leave out a battlefield units can't be played to (`battlefieldTakesUnitsFrom`: `blocks_unit_play`, `units_play_base_only`), so a card needs no mask of its own, and a hidden card's battlefield that is blocked gives no location at all. Behind them the executor refuses: `EffectExecutor::playIgnoringCost` / `playPayingCost` do not play a unit to a location `unitMayBePlayedTo(player, where)` rules out — a base that is not the player's own, a battlefield where units can't be played, any battlefield for a player who may only play to base — and return false with the card left in the zone it was in (for "banish it, then its owner plays it to the same location" that is Banishment: Vendetta FAQ on Temporal Breach). Who controls the battlefield is not part of that test: an effect that names a location ("to the same location", "to any battlefield") replaces the default of CR 355.2.a, not a "can't" (CR 054.1). A battlefield slot's static rules follow the card in it: `replaceBattlefieldWithToken` / `restoreReplacedBattlefield` re-read them (`applyBattlefieldCardRules`), and both take the outgoing battlefield card out through `leftBoard`; a card never moves a battlefield card by hand.
- **Standard Move (CR 144.3)**: the generator emits one intent per (unit, destination) from `GameEngine::standardMoveDestinations`; `executeStandardMove` then asks which other units join the same move (a `MakeChoice` per added unit, first option "Move no more units") and charges `BattlefieldState::multi_move_tax[player]` [A] per unit beyond the first. `GameObject::cant_move_this_turn` stops Standard Moves and its controller's effect moves until the Expiration Step. The units move as one action: all are exhausted, then all are moved, then the `UnitMovedEvent`s are emitted, so a trigger on the first unit's move sees every unit arrived.
- **Might-dependent auras**: an effect whose condition is Might ("While I'm [Mighty] ...", "units with less Might than me") overrides `hasMightDependentAura()` + `applyMightDependentAura()`; `recalculateAuras` calls it after folding every ordinary aura and folds again, so the answer never lags a pass and never counts its own grant.
- **Settling before the main-phase decision**: `advanceMainPhase` runs staged showdowns / combats and the chain, with a cleanup after each round, until nothing is pending — the turn player is never asked with an item on the chain. `combatResolutionStep` resolves the chain where CR 468.2 / 468.4 say so and, on No Result with both players present, keeps the battlefield Contested so another combat is staged (CR 468.3.d.1).
- **Hidden plays**: `generateHiddenPlayActions` serves Closed States and showdowns; a hidden spell's targets are restricted to its battlefield slot by slot, a card frees a slot with `Card::hiddenTargetFreeOfBattlefield(slot)` (CR 811.1.d.4). That covers targets named in the play intent. A choice a card makes through its own pick list is bound by the card, with one rule in `card_helpers.h`: `hiddenBinding(state, source)` (a hidden spell: the battlefield it was played from, 811.1.d.2; a hidden permanent's play effect: the battlefield it is at, none once it has left, 811.1.d.3) and `atHiddenBattlefield(state, source, options)`, which filters a list of board objects (Windsinger, Blastcone Fae, Kennen, Keeper of Balance's play effect). `pickTokenDest` / `tokenPlayDests(ctx)` / `tokenPlayLocations(ctx)` read it themselves (811.1.d.5), as `playLocations(..., only_bf)` does for a card that passes `facedownPlayBattlefield`. A card whose own restriction rules the battlefield out ("at another location": Tideturner) does not call them. The facedown stamps (`__played_from_facedown`, `__facedown_play_bf`, `__facedown_play_turn`) are per-play flags: `Card::forgetPlayPayments` drops them as every play begins, like `kAdditionalCostPaid` and the granted-[Accelerate] mark (`Card::kGrantedAccelerate`).
- **Victory Score**: cards read `GameState::effectiveVictoryScore()`, never `mode.victory_score`.
- **Threading model**: `BatchRunner` wraps `boost::asio::thread_pool`. `GameRunner` is per-game, fully thread-safe (all state stack-local). Shared singletons: `CardDB` (const), `CardRegistry` (const). Per-game: `EventBus`, `GameState`, `GameEngine`, agents, I/O. `AggregateResults` uses atomics for counters, mutex for console output.
- **`on_decision` callback** fires at every decision point including mulligans, combat damage, and chain priority. Trivial single-option decisions are auto-skipped in render.
- **What a player has been shown (knowledge tracker)**: `GameState::knowledge` (`engine/knowledge_tracker.h`, read through `KnowledgeView`) records what each player knows about cards in hidden zones. It hears of it in two places, and card code tells it nothing itself. **Reveals and looks**: a card announces them with `CardRevealedEvent` (audience: `revealed_to_all`, else `revealed_to`); the engine's handler `knowledge::recordReveal` calls `knowledge::shown(state, card, seers)`, which records the card where it is (a hand, facedown, held by a look, or its slot from the top of a deck). A look that announces no event (Void Hatchling's, "look at the top N" before an offer) calls `knowledge::shown` directly. **Moves**: every change to a Main Deck goes through `engine/deck_ops` (as before), and so does every card that enters a hand (`deck::putInHand`, `deck::drawTop`) or a facedown pile (`deck::putFacedown`): a card both players could see is then known to be in that hand, and a card that leaves a hand unseen makes what the other player knew of that hand uncertain. Never `hand.push_back` in engine or card code (`KnowledgeOnePlace.*` scans for it). When an effect itself identifies a card from a hidden zone as it moves ("They reveal their hand. Choose a card from it, and recycle that card"), pass the players who can tell to `recycleCards(..., shown)`. `knowledge::check(state)` lists any claim that disagrees with the state; `tests/test_action_ids.cpp` runs it at every decision of 146 random games. The flat state features do not read the tracker.
- **Log audience**: every `LogEvent` carries a `LogAudience` (`core/events.h`) saying which players may read it — both (the default), one (`EventBus::logTracePrivate(player, ...)`: a draw, a mulligan, a look at a deck, a prompt whose options name hidden cards) or neither (`logTraceFor(LogAudience::neither(), ...)`: e.g. a shuffle order). A consumer that shows the log to one seat (the play server in fair-play mode, a per-observer history for training) forwards a line only if `e.visibleTo(player)`. A new trace line that names a card in a hand, a deck or facedown must use the private form.
- **Log lines are built lazily**: write `RIFT_TRACE(bus, "MOVE: " + unit.name + ...)` (also `RIFT_DEBUG`, `RIFT_INFO`, `RIFT_WARN`, `RIFT_TRACE_PRIVATE(bus, player, msg)`, `RIFT_TRACE_FOR(bus, audience, msg)`, `RIFT_LOG_FOR`; `core/events.h`), not `bus.logTrace(...)`: the message expression is evaluated only while someone reads the log (`EventBus::logging()`: a slot on `on_log` and no quiet stretch). So a message must have no side effects, a line starting with "DECISION #" uses `RIFT_TRACE_DECISION`, and code that builds a string ahead of the call does it under `if (bus.logging())` and calls `bus.noteUnheardLine()` otherwise (the `[D:NNN.NN]` counters advance for an unread line, so a listener attached in mid-game sees the prefixes it would have seen from the start).
- **Logging levels**: `--debug` shows trigger firings and ability resolution. `--trace` adds every phase transition, decision, intent, effect, draw, discard, rune exhaust/recycle, damage assignment, kill, score, counter, equip, token, burn out, and mulligan with card names.
- **HTML replay**: `riftbound --render-html on` writes `<replay-dir>/<timestamp>/replay.html` (single game) or `<replay-dir>/<timestamp>/replay_gameN.html` (batch), with UUID, seed, board state + decision + trace log panels, arrow-key navigation, ★ SCORE banner on scoring snapshots, clickable card-name lookups.
- **State features** (`src/ml/feature_extractor.{h,cpp}`): a state vector of `kStateFeatureDim = 10944` floats: 10932 of content and a 12-float zero block `layout::kPadding` that rounds the length up to a multiple of 16 (it carries nothing; a new block goes before it). It is derived from `kCardVocabSize = 2048`, a power of two: ids 1..955 are registered through Vendetta (`ml::kLastRegisteredCardId`), 956..1165 are reserved for Radiance (210; it needs 169 to 174 by the gallery data), 1166..1565 for Legacy (about 400), 1566..2048 are spare — and that is where test-only cards get their ids, never in a set's range. The derivation and what the size costs (`InfoSetId` 6.5 µs per call) are in `docs/checkpoint-breaking-2026-10.md`, section 0. `openspiel::kNumCardDefIds` must equal `kCardVocabSize` (static_assert in `riftbound_state.cpp`); changing either, or the layout, invalidates trainer checkpoints. **One ordering convention: everything is relative to the perspective player** — self first, opponent second; a field that names a player is 1 = self, 2 = opponent, 0 = nobody; no field says Player1 or Player2, so the vector of a position from one seat equals the vector of the seat-swapped position from the other (`FeaturePerspectiveGames.SeatSwapGivesTheSameVectorAtEveryDecision`). Who goes first is a feature (`layout::kGlobalSelfStarts`); the seat is not. Every block has a named offset in `ml::layout` (use the names, not numbers) and the extractor throws if a block does not start there. Hidden information is masked per perspective (the opponent's hand and deck are never written). `RiftboundState::ObservationTensor` is this vector; `InfoSetId(p)` hashes p's vector with p's seat, the decider and, for the decider, the action ids on offer. **No torch dependency** — plain `vector<float>`. The layout as of the 2026-10 checkpoint break, block by block: `docs/checkpoint-breaking-2026-10.md`.
- **Keywords on a def are the card's own** (plans/08 item 8.8): `CardDef::keywords` (and `assault_value` / `shield_value` / `deflect_value`) hold what the card prints for ITSELF, never a keyword its text gives to something else ("Give a unit [Assault 3]", "a Sprite token with [Temporary]", "Your Mechs have [Shield]") or that belongs to one of its abilities. A permanent has `Keyword::Reaction` only if the card is a [Reaction] card (its class overrides `hasReactionTiming()`) or has [Quick-Draw] (CR 819.1.b); a "[E]: [Reaction] — ..." ability is `ActivatedAbility::is_reaction` (`isReactionAbility()`), and an [Ambush] unit's timing comes from `Keyword::Ambush` (CR 822.1.b). No permanent carries `Keyword::Action`. `LedgerTest.Defs_*` checks this over the whole registry.
- **Coin toss**: `TurnState::starting_player` records who won the coin flip (CR 116).
- **Empower / Empowered (Vendetta, CR 442-443, 827-828)**: `GameObject::empowered` is the status count (binary unless `Card::maxEmpower()` > 1). A card that prints `[Empower] [cost]` overrides `Card::empowerSpec()`; the base `activatedAbilities()` appends it as an `ActivatedAbility{is_empower}` and the engine gates it ("only if not Empowered", `Card::canActivateAbilityAt`), pays it, and resolves it via `EffectExecutor::empower`. `[Empowered][>]` passives go through `forEachEmpoweredSelf` in `applyPassiveAura`. Triggers: `WhenIBecomeEmpowered`, `WhenYouEmpower`. "Disempower this" as a cost is `ActivationCost::disempower_self`. Empowered is cleared when an object leaves the board, with every other status (see "Leaving the board" below).
- **Flow (Vendetta)**: a spell overrides `Card::flowCost()`. `GameEngine::refreshFlowGrants` (end of `recalculateAuras`) rebuilds a standing `TrashReplayGrant{banish_after}` per Flow spell in a trash, so the existing trash-replay generator/payment handles it; paying sets `GameObject::banish_on_leave_chain` and `ChainManager` banishes instead of trashing.
- **Burn (Vendetta, CR 441)**: `EffectExecutor::burn(player, n)` moves the top N of the Main Deck to trash (burning out mid-way per CR 441.4 via `burnOut`) and emits `ObjectStateChangedEvent "burned"` → `WhenYouBurn`.
- **String-keyed state events**: `ObjectStateChangedEvent{id, "<what>"}` is the cheap channel for new trigger sources (`"empowered"`, `"burned"`, `"banished_owned"`, `"discarded"`, `"played_not_from_hand"`, …) — dispatch lives in `TriggerManager::onObjectStateChanged`, so adding one needs no header change. The key is a `StateChangeKey` that refers to its string literal (no copy, no allocation): only a literal converts to it, and it compares with `==` against a string.
- **Activated-ability costs**: `ActivationCost::energy` / `power` (+ `power_domain` / `power_any_domain`) after reductions are `GameEngine::netActivationCost`; `canPayActivation` is the one predicate the ability generators and `payAndQueueAbility` share. "Banish this" as a cost is `ActivationCost::banish_self`, paid with the rest as the ability is activated. `payAndQueueAbility` refuses an activation whose source is not in play (board or Legend Zone), is not the activating player's, or fails `Card::canActivateAbility` / `canActivateAbilityAt`.

## Lessons learned / pitfalls

- **Never put card-specific logic in `game_engine.cpp`.** All card behavior belongs in Card subclass overrides. Engine dispatches; cards decide.
- **Counter spells must NOT directly manipulate the chain.** Use peek-and-pop: the counter resolves (popped by FEPR), then pops the next spell. Never set flags or scan the chain — if the counter is countered first, its `onResolve` never runs, so the target is naturally preserved.
- **AoE damage must collect targets BEFORE killing.** Deal damage to all targets first, then iterate again to kill lethally damaged units. Killing during the damage loop causes iterator invalidation.
- **`addAbility()` must close state** (`oc_state = Closed`). Without this, `generateSpellActions` falls through to `isNeutralOpen()` and allows Action spells during ability chain resolution.
- **Duplicate card names across sets** exist (e.g., "Karma, Channeler" IDs 235 and 548). Each needs its own Card object, with the card id suffixed to the class name.
- **Channeled runes enter READY during channel phase** (CR 316), but card effects that say "channel N runes exhausted" must enter EXHAUSTED. The `channelRunes()` method has an `enter_exhausted` parameter.
- **The mulligan is a single atomic decision** — agent picks which cards (0-2) to set aside in one intent. Cards are removed, replacements drawn, then set-aside recycled. The agent cannot see drawn replacements before deciding. Order: set aside → draw → recycle (CR 118).
- **Death replacement effects are card-owned**, not text-matched: a card overrides `Card::hasReplacementEffect()` / `applyReplacement(ctx, dying_unit)` and returns true when it replaces THAT unit's death. Both kill paths (`GameEngine::killUnit` and `EffectExecutor::killObject`) ask the dying unit's controller's cards in play and the battlefield card where it is dying; the first that returns true consumes the death.
- **The engine does not read `ability_text`.** Replacement effects in `killUnit()`, play-location permissions and battlefield restrictions are all Card virtuals. Repeat costs are `Card::repeatCosts()`.
- **The render shows board state BEFORE resolution.** A chain item may be visible but its effect hasn't happened yet. The trace log in HTML replay shows what happens between renders.
- **`cardDefId()` is not `ctx.source`.** `cardDefId()` is the static card template id (a `CardDefId`, the card's own `def().id`); `ctx.source` is the runtime `GameObjectId`. They are different types, so passing one for the other is a compile error. The place left to get it wrong is an integer slot: what `resume_data` or a `card_counters` value holds is whatever kind was written with `raw()`, and must be read back with the same kind's `fromRaw`.
- **OpenSpiel rollouts have no internal length cap.** `RandomRolloutEvaluator` runs `while(!IsTerminal) ApplyAction(random)`. If the engine produces a state that never reaches a natural terminal under random play, the rollout spins forever inside `MCTSBot::MCTSearch`. Mitigation: `RiftboundState::IsTerminal()` has a hard cap at `MoveNumber() >= kMaxGameLength` (600, `riftbound_game.h`). The engine's own `MctsAgent` / `IsMctsAgent` do not roll out: they score a leaf with `RiftboundHeuristicEvaluator` (score difference) in `agents/mcts_agent.cpp`.
- **Engine bounds throw.** A card that keeps asking (the resume loop in `ChainManager::stepResolve`, `GameEngine::runFinalizePass`) hits a bound and throws `std::logic_error` naming the card; so do the chain's loop (2,000 passes, naming the newest item — except the mandatory loop that is a draw, see "Loops"), a priority window that never ends in both players passing, 500 actions in one Main Phase, 100 in one showdown, 20 consecutive Cleanups that still change the state (CR 322) and 8 passes of the Expiration Step. **An offered option that cannot be executed throws too**: an intent chain priority or Focus has no branch for, and a play offered at chain priority that puts nothing on the chain (there is no "dropped play" list). A concession ends the game at whatever decision it is given (`GameEngine::askAgent`). `GameEngine::applyChoice` throws `std::out_of_range` on a bad index and `RiftboundState` throws `std::invalid_argument` on an action that is not legal. An engine exception ends the game as a failure (`termination_reason == "engine_error"`, a batch exits non-zero), never as a draw.
- **Token cease-to-exist (CR 183.1).** Tokens routed to any non-board zone cease to exist immediately. Both `EffectExecutor::killObject` and `GameEngine::killUnit` route tokens to Banishment WITHOUT adding to `player.banishment` vector. Tokens copied via Mirror Image inherit `card_def_id` so death triggers still fire.
- **Combat designations follow the combat, not the trigger (CR 323.2).** `GameEngine::processContestedBattlefields` re-derives `combat_designation` in every cleanup: a unit at a battlefield with `combat_in_progress` has its controller's designation, a unit anywhere else has none, and combat resolution clears them all. So a designation is still set while that combat's showdown resolves "when I attack / defend" triggers, and gone once the unit leaves the battlefield or the combat ends. It says what a unit is now, not which attacker caused a trigger: `TriggerManager` therefore records the attacking unit in the defender's `card_counters["__defend_attacker_id"]` when `WhenIDefend` fires, and a card that needs "the attacker" reads that at `onTrigger` time (see `OverzealousFan`, 449) instead of scanning the board.
- **Action slots and twins.** Distinct legal intents always get distinct action ids (`actionIds`), so an option can no longer be lost to a collision. What a card can still get wrong is the slot's meaning: options that differ only in a field the slot does not read are twins, told apart by an order of object ids and not by what they are. Give a prompt's options distinct `chosen_value`s or objects (`GameEngine::askAgent` refuses a prompt whose options do not differ by value, object or named card), and prefer `needsPlayTimeTarget` + `pickTarget` / `ActivatedAbility::needs_activation_time_target` to one intent per target.

## OpenSpiel integration knowledge

### Build mechanics

- OpenSpiel's CMake reads **environment variables**, not cache vars, for its build options. Set via `set(ENV{OPEN_SPIEL_BUILD_WITH_*} "OFF")` from the parent project.
- OpenSpiel doesn't ship abseil-cpp / nlohmann/json as submodules; `install.sh` clones them and `sudo apt-get`s system packages. We clone abseil + json + pybind11_json + DDS ourselves in our parent `CMakeLists.txt`.
- `open_spiel_core` is an OBJECT library; its PUBLIC includes only expose `${open_spiel-src}/open_spiel`, not the parent. Add `target_include_directories(YOUR_TARGET PRIVATE ${open_spiel_SOURCE_DIR})` and replicate the abseil link list from OpenSpiel's directory-level `link_libraries(...)`.

### Resume pattern for in-flight chain resolution

- `ChainItem::resume_point` (int) + `resume_data` (vec<int32_t>) save progress.
- `ChainState::resuming` (`optional<ChainItem>`) holds the resolving item across iterations.
- `EffectExecutor::{requestChoice, recordChoice, takeChoice, applyDiscard}` publishes/consumes a choice slot.
- `ChainManager::stepResolve` pops to `resuming`, calls `resolve_spell` in a `while(true)`, breaks on no pending choice. Counter spells unaffected (they peek `items.back()`, not `resuming`).
- The choice helpers compose in any order within a single callback (see "Resumable agent choices" above). A card that drives `resume_data` by hand and also calls a pick* helper leaves slots 0..6 to the helpers.

## Adding state to `feature_extractor`

When you add a field to `GameState` / `PlayerState` that should be visible to a future ML agent, add a block at the end of `ml::layout` in `src/ml/feature_extractor.h` (`kStateFeatureDim` follows `layout::kEnd`) and append the new dims to `extractStateFeatures` in the `.cpp`, self first and opponent second like every other block; `FeaturePerspectiveGames.SeatSwapGivesTheSameVectorAtEveryDecision` fails for a block that names a seat (extend the test's `mirrorSeats` if the new field holds a `PlayerId`). This is what `RiftboundState::ObservationTensor` reports to OpenSpiel. It is a checkpoint break: say so in a `docs/checkpoint-breaking-*.md`. The trainer repo's `docs/additional-gamestate-dims.md` documents the dim layout + a backlog of additional fields to expose.

## Important game rules

- **Victory Score:** 8 points (1v1).
- **Battlefield Count:** 2 at start, can grow via token battlefields.
- **Winning Point (CR 466.1.b):** Via Hold = always works. Via Conquer = must have scored EVERY battlefield (including tokens) this turn. Via card effect = no restrictions.
- **Cleanup (CR 319):** Fires after nearly every state change. Reentrant. 9-step process.
- **Units enter exhausted** (CR 143.4) unless Accelerate or similar.
- **Gear enters ready** (CR 149.1).
- **Rune pools empty** at end of draw phase and end of turn.
- **Replace (CR 438):** Original goes to Banishment, token takes its place, can swap back.
- **Token cease-to-exist (CR 183.1):** Tokens routed to any non-board zone cease to exist immediately.
- **Ambush (CR 822.1.b):** grants a play location (a battlefield where you control units) and [Reaction] timing while played there. It does NOT make the unit enter ready.

## Card data

Card data is **hand-authored C++** — there is no `registry.json`, no `ban-list.csv`,
and no code-generation pipeline. Each card's class implements `Card::def()` returning
its `CardDef` (cost, domains, tags, keywords, art URL, `banned` flag, …); `CardDB` is
materialized from those at startup (`buildFromClasses`). To add or change a card, edit
its `src/cards/<type>/<id>_<slug>.cpp` directly.

- `scripts/fetch_cards.py` — pulls raw card metadata (art, artist, rarity) from the
  official gallery (playriftbound.com) into `cards/raw/gallery_raw.json`, for reference when authoring new
  cards. It does NOT feed the engine.
- `./build/riftbound --dump-registry <path>` — exports the compiled card table to
  registry-style JSON (validation / external consumers).
